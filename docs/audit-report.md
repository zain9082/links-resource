## A. Security sanity check

**Clean in the checked-out source for the requested compromise indicators.** Repo search found no `togel`, `toto`, `lotto`, `gacor`, `casino`, `judi`, `eval(`, `atob(`, or external executable `<script src=...>` in app source/config. The only `slot` hit is the legitimate Radix `Slot` UI component; other substring hits are ordinary CSS/text. All JSX `<script>` tags inspected emit local JSON-LD. `src/proxy.ts` guards `/admin` by authentication/role; no user-agent or bot-specific routing. No `middleware.ts` or `vercel.json` exists; `next.config.ts` contains redirects but no rewrites or headers. The SEO audit utility sets a user-agent for its **outbound fetch** only.

Production was not fully source-audited because its deployed code is not present in this checkout. The live `sync-probe` URL is an SEO/data hygiene problem, not evidence of compromise by itself. Search Console's clean manual-action/security status is consistent with this limited check.

## B. Technical SEO state and issues

### Metadata and indexing

`src/lib/seo.ts` supplies title, description, absolute canonical, Open Graph (`en_GB`), Twitter and robots via `buildMetadata`; `src/app/layout.tsx` sets defaults. Static public pages override it, while `/resources/[slug]`, `/categories/[slug]`, and `/tags/[slug]` use `generateMetadata`. Auth/admin pages are `noindex`; search is `noindex,follow`; the 404 component is `noindex`. All **39 production sitemap URLs tested** returned a canonical tag; there are no missing canonicals in that inventory. This does **not** validate the canonical *target* or every non-sitemap URL. The invalid `sync-probe` URL returns 200 with a self-canonical and a “Not found” title. The 404 component inherits a root `/` canonical in this checkout, so error responses need explicit verification. `src/app/layout.tsx` has `lang="en"`, while OG locale is `en_GB`; use `en-GB` for UK targeting. No hreflang was found in source; a UK-only English site does not require it.

`src/app/sitemap.ts` in this branch lists static routes plus hard-coded `resources`, `categories`, and `tags` from `src/lib/data.ts`, with **no `lastModified` values**. Production's sitemap instead has a shared `2026-09-08T18:03:13.825Z` lastmod across static/category URLs and item-specific resource timestamps, including `sync-probe`; that strongly indicates a deployed sitemap implementation assigning a batch/build timestamp and including persisted resource records. Exact production source needs inspection before changing it. Use true per-page publication/update dates; omit `lastmod` where none is trustworthy. Exclude test/invalid records, noindex and 404 pages, and make invalid slugs return a real 404. `robots.txt` comes from `src/app/robots.ts` in this checkout. Production `robots.txt` additionally disallows `/login/`, `/signup/`, and `/search/`, another deployment mismatch.

Source structured data: sitewide `ProfessionalService` (a `LocalBusiness` subtype) and `WebSite` in `src/lib/seo.ts`/`src/app/layout.tsx`; `Service` and `BreadcrumbList` on data-driven service/resource pages; `BreadcrumbList` on category/tag pages; `FAQPage` on homepage. `Organization` appears as the `Service.provider` type, but there is no standalone `Organization` root node. The service hub/case-study pages have no specific Service/Breadcrumb schema in this checkout. Validate production schema separately after the deployment source is reconciled.
